# Задание агенту: развернуть калибровку Dell U4025QW

Ты помогаешь развернуть уже готовую калибровку монитора на новой машине.
Всё исследование проведено, параметры найдены — переоткрывать их не надо.
Твоя задача: развернуть, проверить на этом конкретном экземпляре панели
и довести до рабочего состояния.

Все файлы лежат в папке рядом с этим документом. Начни с `CLAUDE.md` —
там полный контекст. Здесь только то, что нужно для выполнения.

---

## Целевая конфигурация

| ручка | значение | где |
|---|---|---|
| HDR в Windows | включён | Win+Alt+B |
| Слайдер «Яркость контента SDR» | **43%** — ставится один раз, яркость им не меняется | Параметры → Система → Дисплей → HDR |
| Яркость белого | **140 нит** — задаётся кривой | `Display-Tuner.bat` |
| Гамма в LUT | **2.6** | `lut-s252-w140-g26.cal` через `dispwin` |
| Digital Vibrance | **55%** | NVIDIA → Display → Adjust desktop color settings |
| Пресет монитора | **DisplayHDR 600** | OSD, Smart HDR |
| Sharpness | **50** | OSD, Display |
| Auto Brightness / Auto Color Temp. | **Off** | OSD, Brightness/Contrast |
| Формат вывода | RGB · Full · 10 бит | NVIDIA → Change resolution |

Три ручки независимы: **яркость (кривая), гамма (контраст), Digital Vibrance
(насыщенность).** Не подменяй одну другой.

Кривая принимает два уровня белого: `SliderNits` (куда Windows кладёт белый SDR,
фиксирован на 252) и `WhiteNits` (фактическая яркость, свободна). Генератор —
`LutGen.ps1`, подключается через точку.

## Порядок

### 1. Предпосылки

- В мониторе `Menu → Others → DDC/CI → On`. Без этого не прочитать настройки.
- Проверь видеокарту: `Get-CimInstance Win32_VideoController | Select Name`.
  Digital Vibrance есть только у NVIDIA. У AMD эквивалент —
  `AMD Software → Display → Custom Color → Saturation`, у Intel —
  `Graphics Command Center → Display → Color → Saturation`.

### 2. Развернуть

```powershell
.\Setup.bat
```

Скрипт генерирует кривую сам (математика PQ на PowerShell, Python не нужен),
печатает список ручных шагов, ждёт Enter, грузит кривую и проверяет рамп.

**Порядок внутри критичен: слайдер SDR-яркости чистит гамма-рамп, поэтому
кривая грузится последней.** Если пользователь двинул слайдер после загрузки —
кривая молча слетела, нужен `reload.bat`.

### 3. Проверить на этом экземпляре

Модель та же, но панели разнятся. Две проверки, обе обязательны.

**Потолок белого** (140 нит далеко от потолка панели ~255, так что это скорее
проверка совпадения кривой со слайдером) — `clip-test.html`, пара 255/250 (клавиша `3`), на весь
экран (F11), подержать 30–40 секунд (ABL включается не сразу).

- Полосы различимы → запас есть, всё хорошо.
- Поле ровное → кривая не совпадает с уровнем белого. Перегенерируй под
  фактическое положение слайдера: `Setup.bat -WhiteNits <нит>`,
  где нит = 80 + 4 × процент.

Тест устроен так, чтобы обойти локальное затемнение: полосы двух близких
кодов по всему экрану, внутри каждой зоны подсветки оба кода лежат поровну.

**Тени** — `gray-test.html`, секции 1 и 2. На гамме 2.6 плашки должны
различаться примерно с кода 5, шаги 5–60 ровные. Сливаются до 8–10 — гамма
великовата, переключи на 2.4 через `Gamma-GUI.bat`.

**Цвет** — `color-test.html`, если пользователь захочет менять насыщенность.
Верхние ступени красного должны оставаться различимыми. Красный примари
вынесен за sRGB дальше остальных и упирается первым, поэтому при переборе
насыщенности схлопывается именно он.

### 3a. Приложение

`Display-Tuner.bat` — ползунки яркости и гаммы, профили, значок в трее,
настройки в `tuner-settings.json`. Ключ `-Apply` применяет сохранённое
без окна — именно его вызывает задача автозагрузки.

### 4. Автозагрузка

```powershell
.\Setup.bat -RegisterAutoStart
```

От администратора. Без неё кривая слетает при перезагрузке.

## Верификация

Не верь на слово, проверяй рамп. `Setup.ps1 -Verify` делает это сам, но если
нужно вручную — читай через `GetDeviceGammaRamp` из `gdi32.dll` и сравнивай
с identity (`v[i] == i*257`). Нулевое отклонение = кривая НЕ загружена.

Опознать, какая именно кривая в рампе, можно сверкой с `.cal`-файлами —
готовая логика есть в `Gamma-GUI.ps1`, функция `Get-LoadedGamma`. Остаточное
расхождение до ~2000 — это округление при передискретизации 1024 → 256.

Настройки монитора: `.\Monitor-VCP.ps1 -Dump`.

## Тупики — туда не ходить

Всё перечисленное проверено и закрыто. Не трать время.

- **Насыщенность в HDR поднимается ТОЛЬКО через Digital Vibrance драйвера.**
  Ползунки Hue/Saturation в OSD доступны лишь в SDR-пресетах Movie/Game —
  в HDR меню Color подменяется списком Smart HDR. По DDC/CI коды `8A` и `90`
  монитор не отдаёт: их нет в строке возможностей (проверено через
  `CapabilitiesRequestAndCapabilitiesReply`). Windows HDR Calibration эффекта
  не даёт.
- **Гамма — это не насыщенность.** Поканальная степень разводит каналы вниз:
  цвет сочнее, но картинка темнее и тени закрываются. На 2.8 порог теней
  уползает с кода 5 к 8–10. Отвергнуто.
- **1D-кривая матрицу насыщенности не заменит.** `.cal` и vcgt одномерные,
  красный на выходе зависит только от красного на входе. Файл, поднимающий
  насыщенность, сгенерировать нельзя в принципе.
- **SDR-режим отвергнут.** Там цвета сочнее (монитор растягивает sRGB на
  нативный гамут) и белый до ~349 нит, но чёрный серый: локальное затемнение
  работает только в HDR. Глубина чёрного оказалась важнее.
- **Контраст в HDR не пишется.** DDC-команда принимается, значение остаётся
  прежним — Dell блокирует настройку. Значение 100, которое читается в HDR,
  относится к HDR-пресету и на картинку не влияет.
- **Game HDR отвергнут.** Добавляет подчёркивание краёв (лечится Sharpness 30),
  и у него свой потолок белого, под который кривая не считана.
- **Локальное затемнение не отключается** — на этой модели его нет в OSD.

## Грабли окружения

- **Имена переменных в PowerShell регистронезависимы.** `$N` и `$n` — одна
  переменная. На этом уже погорел генератор кривых: счётчик цикла `$N`
  затирался строкой `$n = $i / ($N - 1)`, и в файл попадала одна строка
  вместо 1024. Проверяй число строк в сгенерированном `.cal`.
- **PowerShell 5.1**: `&&` не работает, разделитель `;`. Нет тернарного
  оператора и `??`. `ConvertFrom-Json` даёт PSCustomObject, не хэштаблицу.
- **`.ps1` с кириллицей нужен UTF-8 с BOM.** Без BOM PowerShell 5.1 читает
  файл в ANSI и падает на разборе строк.
- **DDC/CI — медленный I2C-канал.** Транзакции подряд срываются: делай
  повторы с паузой 150 мс, иначе показания скачут и выглядят как
  неподдерживаемые коды. Готовые обёртки — в `Monitor-VCP.ps1`.
- **Меню Brightness/Contrast в мониторе заблокировано, пока на входе HDR.**
  Чтобы туда попасть: Win+Alt+B, поменять, включить обратно.
- **На странице цвета драйвера трогать только насыщенность.** Brightness,
  Contrast и Gamma там пишутся прямо в гамма-рамп и затирают кривую.
  `Color accuracy mode` держать на Accurate; в reference-режиме коррекция
  из рампа не применяется вообще.
- **Нативный HDR-контент кривая тоже давит.** Перед HDR-играми `reset.bat`,
  после — `reload.bat`.

## Что спросить у пользователя

Эти вещи нельзя выяснить из системы, только глазами:

1. Результат `clip-test.html` — различимы ли полосы при слайдере 43%.
2. Результат `gray-test.html` — с какого кода начинают различаться тени.
3. Устраивает ли насыщенность на 55% или подобрать другую.

Слайдер SDR-яркости программно не читается и не пишется — API у Windows нет,
только руками. Digital Vibrance тоже: NVAPI из PowerShell без обёртки
недоступен. Обе величины запрашивай у пользователя.
